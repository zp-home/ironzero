# 训练输入维度与奖励/惩罚机制一览

> 代码依据（当前工作区）：`src/ironzero/observation/encoding.py`、`observation/features.py`、
> `observation/masks.py`、`observation/terrain_channel.py`、`micro_config.py`、
> `rwpp/config.py`、`rwpp/reward_shaping.py`、`rwpp/reward.py`、`rwpp/strategy.py`、
> `engine/reward.py`、`training/ppo.py`、`training/policy.py`。
> 观测/动作维度的唯一定义来源是 `MicroDuelConfig`（`flat_obs_dim` / `action_nvec`）。

## 1. 模型输入：观测向量（一条 `float32` 平铺向量）

四段拼接，`encode_observation()` 末尾有 `assert offset == cfg.flat_obs_dim` 兜底。

| # | 段 | 维度 | 归一化 | 说明 |
|---|---|---:|---|---|
| 1 | 全局块 global | `global_dim` = 15 | 有 | 时钟、兵力、血量、质心、经济 |
| 2 | 己方实体块 own_entities | `max_entities × entity_features` = 8×10 = 80 | 部分 | 按优先级重排后按 slot 填，空位补零 |
| 3 | 敌方实体块 visible_enemy | 同上 = 80 | 部分 | **不重排**（target 头按此列表索引） |
| 4 | 控制网格 map_grid | `map_channels × 8 × 8` = 3×64 = 192 | 通道 0..2 除以 `units_per_team` | 密度/控制差/地形先验 |
| 合计 | | **367**（默认 8v8、3 通道） | | |

### 1.1 全局块（15 维，按偏移顺序）

| 偏移 | 特征 | 公式 | 值域 |
|---:|---|---|---|
| 0 | 时间进度 | `tick / episode_ticks` | [0,1] |
| 1 | 己方存活数 | `len(own) / units_per_team` | [0,1] |
| 2 | 敌方可见数 | `len(enemy) / units_per_team` | [0,1] |
| 3 | 己方血量比 | `Σown_hp / Σown_max_hp(首帧)` | [0,1] |
| 4 | 敌方血量比 | `Σenemy_hp / Σenemy_max_hp(首帧)` | [0,1] |
| 5 | 己方质心 x | `own_cx / map_width` | [0,1] |
| 6 | 己方质心 y | `own_cy / map_height` | [0,1] |
| 7 | 敌方质心 x | `enemy_cx / map_width` | [0,1] |
| 8 | 敌方质心 y | `enemy_cy / map_height` | [0,1] |
| 9 | 相对位移 x | `(enemy_cx − own_cx) / map_width` | **[-1,1]** |
| 10 | 相对位移 y | `(enemy_cy − own_cy) / map_height` | **[-1,1]** |
| 11 | 常数偏置 | 恒 `1.0` | 1 |
| 12 | 资金 | `funds / 5000` | [0,1] |
| 13 | 收入速率 | `income / 40` | [0,1] |
| 14 | 已占资源点 | `occupied_slots / 4` | [0,1] |

注：血量分母用**首帧（episode start）**的 `Σmax_hp`，不是 `units_per_team × unit_hp`，
所以建筑（4000 HP 指挥中心）不会把特征顶到 10 以上。

### 1.2 实体块（每位实体 10 维，己方/敌方各 `max_entities` 个 slot）

| 索引 | 特征 | 公式 |
|---:|---|---|
| 0 | 占位掩码 | 该 slot 有实体为 1，否则 0（全零填充） |
| 1 | 绝对 x | `x / map_width` |
| 2 | 绝对 y | `y / map_height` |
| 3 | 血量比 | `hp / max_hp` |
| 4 | 分组号 | `group_id / (groups−1)`；缺失时用 `entity_id % groups` |
| 5 | 当前指令 | `ORDER_ID / (len(ORDER_IDS)−1)`，`idle/move/attack_move/attack_target/hold` → 0..4，除以 4 |
| 6 | 相对质心 x | `(x − own_cx) / map_width` |
| 7 | 相对质心 y | `(y − own_cy) / map_height` |
| 8 | 最近敌人方向 x | 己方：`(nearest_enemy.x − x)/map_width`；敌方：`(x − own_cx)/map_width` |
| 9 | 最近敌人距离 | `clip(dist, 1.5)/1.5`（差 1000 px 记 1.0） |

己方块排序：`factory(0) > 其它建筑(1) > builder(2) > 战斗单位(3)`（`prioritise_own`，稳定排序）。
敌方块保持桥接流顺序，保证 `target 头 slot i` 的语义不随我方移动漂移。

### 1.3 控制网格（`map_channels × 8 × 8`）

| 通道 | 内容 | 归一化 |
|---:|---|---|
| 0 | 己方单位计数（每格） | ÷ `units_per_team` |
| 1 | 敌方单位计数（每格） | ÷ `units_per_team` |
| 2 | 控制差 `clip(ch0 − ch1, −1, 1)` | ÷ `units_per_team` |
| 3（可选） | 静态地形可通行先验 `[0,1]`（1=可走） | 不缩放（本身已在 [0,1]） |

通道 3 只有 `map_channels>3` 且配置了 `terrain_path`（如 `configs/maps/IronZero25.terrain.json`）
才存在；文件缺失/解析失败时**维度不变**、通道留零并 `RuntimeWarning`。

### 1.4 规模换算（实测 `flat_obs_dim`）

| 场景 | max_entities | 通道 | obs_dim | 动作头 `nvec` |
|---|---:|---:|---:|---|
| 离线微操默认（8v8） | 8 | 3 | **367** | `(11, 5, 8, 8, 9)` |
| 离线 8v8 + 地形 | 8 | 4 | 431 | `(11, 5, 8, 8, 9)` |
| 真机 25v25（无地形） | 25 | 3 | 707 | `(11, 5, 8, 8, 26)` |
| 真机 25v25 + 地形（`train_rwpp` 示例命令） | 25 | 4 | **771** | `(11, 5, 8, 8, 26)` |

> 文档漂移提醒：`training/train_rwpp.py` 顶部注释写 `action heads (10,5,8,8,26)`，
> 实际 `ACTION_KINDS` 已加入 `noop` 共 **11** 个，所以 kind 头是 11。

### 1.5 没有的输入（不要误以为有）

| 缺失项 | 现状 |
|---|---|
| 观测历史 / 帧堆叠 | 无（`frame_stack` 未实现，策略是 memoryless MLP） |
| 循环记忆 | 无（无 GRU/LSTM） |
| 人口/补给、击杀数、损失数 | 协议里有（`global_state.kills/losses`），**不进观测向量** |
| 战争迷雾记忆 | `remembered_enemies` 字段存在但为空列表 |
| 资源点坐标/等级 | 只有"已占个数"进观测（1 维），坐标不进去 |
| 建筑进度 / 生产队列 / 冷却 | 引擎 payload 有，观测编码不用 |

## 2. 动作头与掩码（策略输出侧，与输入配套）

| 头 | 宽度 | 语义 | 掩码规则 |
|---|---:|---|---|
| kind | **11** | `move_group / attack_move / attack_target / stop / hold / build_extractor / build_structure / produce_unit / upgrade_building / repair_target / noop` | 战术命令恒开；经济类需 `有存活 builder + 引擎报告可建 + 资金够`；整头全 false 时回退前 5 个 |
| group | 5 | 4 个固定单位组 + 1 个"全体广播" | 有 `group_id` 按实际置位；只有 `entity_id` 时 4 组全开；广播槽恒开 |
| x | 8 | 目标格 x | 恒开 |
| y | 8 | 目标格 y | 恒开 |
| target | 9（25v25 时 26） | 敌方 slot 或建造 slot | 前 `min(敌人数, T−1)` 开，最后一槽恒开（"无目标"） |

层级采样：kind 先采，再用 `_active_matrix` 只让该 kind 用到的头进入 log-prob / entropy
（`move/attack_move/build_structure` 用 x,y；`attack_target/build_extractor/produce_unit/
upgrade_building/repair_target` 用 target；`stop/hold/noop` 只用到 group）。

## 3. 真机（RWPP）奖励分解

`reward = sum(components.values())`，**键顺序即浮点累加顺序，不可改**（测试逐位敏感）：
`potential, engagement, strategy, kills, losses, income, bonus_build, invalid, idle, terminal, timeout`。

| 键 | 公式 | 系数（默认） | 单步量级 | 语义 |
|---|---|---:|---|---|
| `potential` | `0.5 × (φ_t − φ_{t−1})`，`φ = 己方HP占比 − 敌方HP占比` | `potential_coef=0.5` | ≤ ±1.0 | 势函数塑形（不改变最优策略） |
| `engagement` | `2.0 × (d_{t−1} − d_t)`，`d` = 双方质心距离 / 地图对角 | `engagement_coef=2.0` | ≤ ±2.0 | 逼近敌人（远距离开局的梯度来源） |
| `strategy` | `0.5 × Δ(strategy_potential)`，strategy = `−dist(己方质心, 指令目标)/对角` | `strategy_coef=0.5` | 小 | LLM/规则战略层的软引导 |
| `kills` | `0.25 × max(0, 上一步敌存活 − 本步敌存活)` | `kill_bonus=0.25` | +0.25/杀 | 击杀奖励 |
| `losses` | `−0.25 × max(0, 上一步己存活 − 本步己存活)` | `loss_penalty=0.25` | −0.25/损 | 己方战损惩罚 |
| `income` | `0.5 × Δincome / 10` | `extractor_reward=0.5` | ≈ +0.9/新建矿 | 只奖励收入**增长**，不奖励持续收入 |
| `bonus_build` | `0.20 × 新建己方建筑数` | `build_bonus=0.20` | +0.20/栋 | 按"建筑数增加"发放，重复下单刷不到 |
| `invalid` | `−0.05 × 被拒回执数` | `invalid_penalty=0.05` | −0.05/次 | 非法/被引擎拒绝的动作 |
| `idle` | 当首个动作 kind ∈ {`stop`,`hold`} 且敌存活时 `−0.02` | `idle_penalty=0.02` | −0.02 | 消极指令惩罚 |
| `terminal` | 胜 `+1.0` / 负 `−1.0`（截断裁决 `×0.8`） | `win_reward=1.0` / `loss_reward=−1.0` | ±1.0 | 终局奖励 |
| `timeout` | 恒 `0.0`（占位键，未使用） | — | 0 | 超时没有独立惩罚 |

### 3.1 终止 / 截断裁决

| 情形 | 判定 | terminal 值 | `result` |
|---|---|---:|---|
| 桥接报 `result=victory/defeat` | `terminated=True`（引擎权威） | `+1.0` / `−1.0` | `victory` / `defeat` |
| 无 result 字段 + 敌全灭 | 全灭启发式 | `+1.0` | `victory` |
| 无 result 字段 + 己全灭 | 全灭启发式 | `−1.0` | `defeat` |
| tick 到 `episode_ticks` / 桥接 `done` / 断线 → 截断 | 比存活数 + HP 占比（阈值 0.08，微操/歼灭局） | 胜 `+0.8` / 负 `−0.8` / 均势 `0` | `victory`/`defeat`/`timeout` |

断线（`disconnected`）一律只截断，不做胜负裁决。

### 3.2 归一化与训练侧处理

| 项 | 做法 |
|---|---|
| 奖励裁剪/缩放 | **无**（PPO 不做 reward clip/normalize，也没有 reward_scale 配置） |
| 优势归一化 | 每 minibatch `(A − mean) / (std + 1e-8)` |
| 折扣 | `gamma=0.99`，`gae_lambda=0.95` |
| 其它 | `clip_ratio=0.2`、`value_coef=0.5`、`entropy_coef=0.01`、`max_grad_norm=0.5`、`lr=3e-4`、`epochs=4`、`hidden=256`（2 层 MLP + 5 头 + 1 价值头） |

## 4. 离线引擎（MicroDuelEngine）奖励分解

`engine/reward.py::_reward_after_window()`，每决策窗口一次。

| 键 | 公式 | 系数 |
|---|---|---:|
| `potential` | `0.5 × (φ_t − φ_{t−1})`，`φ = (己HP − 敌HP) / (units_per_team × unit_hp)` | `potential_coef=0.5` |
| `economy` | `0.5×extractor_built + 0.8×extractor_upgraded` | `extractor_reward=0.5` / `extractor_t2_reward=0.8` |
| `factories` | `0.6 × factory_built` | `factory_reward=0.6` |
| `production` | `0.4 × unit_produced` | `production_reward=0.4` |
| `building_loss` | `−1.0 × building_destroyed` | `building_loss_penalty=1.0` |
| `terminal` | 胜 `+1.0` / 负 `−1.0` | `win_reward` / `loss_reward` |
| （隐式）闲置资金 | 若 `funds > 800`：`−0.0001 × (funds − 800)`，**不单独成键** | `idle_funds_penalty_coef=0.0001` |

注：闲置资金惩罚只存在于离线引擎路径，**真机路径没有**；反过来的 `engagement / strategy /
kills / losses / invalid / idle` 只存在于真机路径。

## 5. 两边共有的惩罚项对照

| 惩罚 | 真机 (rwpp) | 离线引擎 | 触发条件 |
|---|---|---|---|
| 非法动作 | ✅ `invalid` −0.05/次 | ❌（只有回执，不进 reward） | 引擎拒绝订单 |
| 消极指令 | ✅ `idle` −0.02 | ❌ | kind ∈ {stop, hold} 且敌存活 |
| 己方战损 | ✅ `losses` −0.25/单位 | ⚠️ 只通过 `potential` 体现 | 存活数下降 |
| 建筑被毁 | ⚠️ 只通过 `potential` | ✅ `building_loss` −1.0/栋 | 建筑死亡 |
| 闲置资金 | ❌ | ✅ `−0.0001×(funds−800)` | 资金超阈值 |
| 超时 | ⚠️ 无独立惩罚，按 HP 裁决 ±0.8 | ❌ | tick 用尽 |
| 掩码层预防 | ✅ kind/target 掩码 | ✅ 同 | 不可行动作直接不可选 |

## 6. info / 日志里可见但不进模型输入的量

`info` 每步返回，供监控与回放用（`rwpp/stepping.py::build_step_info`）：
`episode_id, tick, result, bridge_result, disconnected, receipts, masks, raw_state,
visible_enemies, actions, own_alive, enemy_alive, distance, reward_breakdown（本步分量）,
reward_components（整局累计分量）, strategy, eval{own_hp_frac, enemy_hp_frac},
max_refs{own, enemy}, port`。

训练曲线（`metrics.json` / live JSONL）落盘：`mean_return, rolling_return, win_rate,
loss_rate, timeout_rate, reward_components, policy_loss, value_loss, entropy,
clip_fraction, episodes`。
