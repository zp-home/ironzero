# 安全与发布检查表

> 文档状态：v0.1 基线
> 作者：周培智
> 适用范围：本机训练、推理、演示、受控内网人机评估和 GitHub 发布
> 配套文档：[环境规格说明](./环境规格说明.md)、[确定性与测试方案](./确定性与测试方案.md)

本文档中的“安全”包含两类：

1. **动作安全**：模型不能执行非法、不可见或危险的动作。
2. **系统安全**：Bridge、模型、扩展、进程、网络和发布过程不能被滥用。

动作安全不能替代系统安全。两者都必须通过检查。

---

## 1. 信任边界

```text
┌──────────────────────────────────────────────┐
│ 不可信输入                                   │
│ 模型输出、配置文件、地图、模组、外部 checkpoint │
└──────────────────────┬───────────────────────┘
                       │ 校验
┌──────────────────────▼───────────────────────┐
│ 安全层                                       │
│ schema、动作掩码、权限、限频、路径、哈希       │
└──────────────────────┬───────────────────────┘
                       │ 受控命令
┌──────────────────────▼───────────────────────┐
│ 游戏线程与游戏对象                           │
│ 只能由受信任的 Adapter 访问                   │
└──────────────────────────────────────────────┘
```

原则：

- 模型输出、网络消息和外部文件都按不可信输入处理。
- Bridge 不直接暴露 Java 游戏对象。
- Python 不直接持有 Java 引用。
- 只有受信任扩展可以在游戏线程执行命令。
- 所有输入都必须校验大小、类型、版本和来源。

## 2. 威胁模型

| 威胁 | 影响 | 主要缓解 |
|---|---|---|
| 恶意或错误模型输出 | 非法动作、崩溃、作弊 | 动作掩码、执行前校验、限频 |
| 本地端口被其他进程访问 | 伪造动作、读取状态 | 回环绑定、token、连接限制 |
| 外部 checkpoint 含恶意代码 | 主机被控制 | 安全序列化、哈希、来源白名单 |
| 不可信模组或扩展 | 任意代码执行 | 信任列表、签名/哈希、隔离 |
| 地图路径穿越 | 读取任意文件 | 规范化路径、根目录约束 |
| 资源耗尽 | 训练中断、系统不稳定 | 限额、超时、监控、进程隔离 |
| 端口和进程泄漏 | 多实例失败 | 进程树清理、端口审计 |
| 内网房间暴露 | 未授权玩家或公网访问 | 防火墙、禁止端口映射、白名单 |
| 日志泄露隐私 | 内网信息外泄 | 脱敏、保留期限、访问控制 |
| 依赖供应链攻击 | 构建或运行被污染 | 锁版本、哈希、SBOM、最小依赖 |

## 3. Bridge 安全

### 3.1 监听范围

- 训练和默认推理只绑定 `127.0.0.1`。
- 不监听 `0.0.0.0`。
- 不使用公网可达地址。
- 每个实例使用独立端口。
- 启动前检查端口占用。

### 3.2 连接认证

即使是本地回环，也建议加入一次性 token：

```text
run_id
episode_id
token
protocol_version
adapter_version
```

要求：

- token 在进程启动时生成。
- token 不写入公开日志。
- 握手失败直接断开。
- 单个实例限制并发连接数。
- 训练结束后 token 失效。

### 3.3 消息限制

必须设置：

```text
max_message_bytes
max_json_depth
max_entities
max_actions_per_decision
max_string_length
max_queue_size
```

要求：

- 超限立即拒绝。
- 不把超限消息完整写入日志。
- 不尝试自动修复结构错误的 JSON。
- 未知字段按协议版本决定拒绝或忽略，不能静默接受。

### 3.4 重放与乱序

- 每条消息带 `episode_id`、`tick`、`sequence`。
- 旧 tick 动作拒绝。
- 重复 decision 拒绝。
- episode 不匹配拒绝。
- 乱序消息不得执行。
- 每个动作执行后记录回执。

## 4. 模型与 checkpoint 安全

### 4.1 序列化格式

优先级：

1. 自己生成的、经过哈希校验的 `safetensors` 或安全权重格式。
2. 经过验证的 TorchScript。
3. 经过验证的 ONNX。
4. 仅在受信环境中使用 `torch.load(..., weights_only=True)`。

禁止：

- 加载来源不明的 pickle。
- 加载未校验的 `.pt` 文件。
- 从网络自动下载模型并直接执行。
- 用模型文件中的配置覆盖服务器安全配置。

### 4.2 模型 manifest

每个 checkpoint 附带：

```text
model_id
model_hash
training_run_id
observation_schema_version
action_schema_version
reward_version
scenario_version
game_version
python_version
pytorch_version
created_at
source
evaluation_report_id
```

加载时必须校验 manifest 和文件哈希。

### 4.3 推理服务边界

- 推理服务不直接访问游戏对象。
- 推理服务不直接监听公网。
- 推理超时由游戏侧安全层兜底。
- 推理服务崩溃不能导致游戏无限等待。
- 模型输出先校验，再进入动作队列。

## 5. 扩展、模组和地图安全

### 5.1 扩展

RWPP 扩展是可执行代码。要求：

- 只从项目控制的 `extensions/` 目录加载。
- 记录扩展名称、版本、哈希和来源。
- 不使用未知来源的 JAR。
- 发布前审查第三方扩展许可证。
- 扩展异常必须被隔离，不能破坏游戏线程。

### 5.2 模组

- 模组版本必须与游戏和场景匹配。
- 训练、评估和演示使用同一版本。
- 模组内容不提交到 Git，除非有明确再分发许可。
- 模组加载失败时拒绝启动 episode。

### 5.3 地图路径

地图路径必须：

- 规范化。
- 不允许 `..`。
- 不允许绝对路径。
- 不允许盘符。
- 必须位于允许的根目录。
- 记录地图哈希。

示例校验：

```text
allowed_roots:
  assets/maps/skirmish
  mods/maps
  saves
```

## 6. 进程、文件与日志安全

- 每个 episode 使用独立运行目录。
- 运行目录不得指向仓库源码目录。
- 临时文件使用系统临时目录或受控 artifacts 目录。
- 进程启动使用参数列表，不拼接 shell 字符串。
- 关闭时终止整个子进程树。
- 端口、PID、日志路径写入 run manifest。
- 日志设置大小上限和轮转。
- 配置文件不包含可公开的 token 或密码。
- token、内网地址、账号和主机名必须脱敏。

### 6.1 急停

必须提供一个独立于模型的急停路径：

```text
急停
  → 拒收新动作
  → 发送 STOP/HOLD
  → 停止策略服务
  → 保持或结束游戏
  → 记录事件
```

急停不能依赖模型推理服务、Dashboard 或网络连接仍然正常。

## 7. 内网人机评估安全

### 7.1 网络隔离

- 服务端在隔离内网运行。
- 禁止公网端口映射。
- 禁止 UPnP。
- 不加入公共服务器列表。
- 防火墙仅允许指定客户端。
- 服务端只监听指定内网地址。
- 评估结束后关闭监听。

### 7.2 参与者

- 所有参与者必须知情并同意。
- 不使用随机玩家或公共匹配。
- 不把 AI 伪装成真人。
- 记录版本、地图、模组和参与者确认。

### 7.3 公平性

- AI 和真人使用相同规则。
- AI 只读取本队可见信息。
- AI 动作频率受限。
- 不允许通过服务端权限修改资源或隐藏单位。
- 对局结果、回放和审计日志必须保留。

## 8. 供应链与依赖

### 8.1 版本锁定

必须锁定：

```text

PyTorch

NumPy

网络库

```

### 8.2 依赖检查

- 使用 lockfile。
- 记录依赖来源。
- 避免不必要的依赖。
- 发布前生成依赖清单或 SBOM。
- 对关键依赖做许可证检查。
- 不使用来源不明的二进制包。

### 8.3 构建产物

- 构建产物不混入游戏 assets。
- 不把反编译产物提交到仓库。
- 不把本地路径、密钥和训练数据打进发布包。
- 发布包提供校验和。

## 9. 许可证与合规

本节不是法律意见。公开发布、商用或分发修改版本前，应核对许可证原文并咨询专业人士。

### 9.1 项目自身许可证

发布前必须确定：

- 代码许可证。
- 文档许可证。
- 是否允许商用。
- 是否要求署名。
- 是否允许再分发。

建议将代码和文档许可证分开记录，但最终选择必须与所有第三方依赖兼容。

### 9.2 RWPP 与 AGPLv3

RWPP 使用 AGPLv3。需要重点审查：

- 是否分发修改后的 RWPP 代码。
- 是否分发链接 RWPP API 的扩展。
- 是否通过网络向其他用户提供修改后的服务端。
- 是否需要提供对应源代码。
- 项目自身许可证是否兼容。

即使只在内网使用，也应保留依赖来源、版本和修改记录，避免后续无法判断义务。

### 9.3 其他第三方项目

对每个第三方项目记录：

```text
name
url
version_or_commit
license
copyright_notice
used_files_or_modules
modifications
```

不要只根据 GitHub 页面上的自动许可证标签判断。要检查仓库中的 LICENSE、NOTICE 和具体文件头。

### 9.4 游戏本体与资源

禁止提交：

- 游戏本体。
- 原版 `assets/`。
- 反编译类文件。
- 未授权的贴图、音频、地图和模组。
- 可替代原版游戏的资源包。

需要确认：

- 游戏 EULA 是否允许研究和自动化测试。
- 是否允许修改客户端或服务端。
- 是否允许分发衍生工具。
- 是否允许公开训练结果和模型。

### 9.5 模型与数据

需要记录：

- 训练数据来源。
- 是否包含真人数据。
- 是否包含游戏资源。
- 模型是否允许公开。
- 是否允许商用。
- 是否需要删除敏感日志。
- 模型卡和评估报告是否随模型发布。

## 11. 事件响应

发生以下事件时必须停止训练或演示：

- 发现模型读取了不可见信息。
- 发现 Bridge 可被未授权进程控制。
- 发现外部模型或扩展执行恶意代码。
- 发现内网服务端暴露到公网。
- 发现游戏资源或第三方代码被误提交。
- 发现训练数据或日志泄露隐私。

处理顺序：

```text
停止接受新动作
  → 保存现场日志和版本
  → 关闭游戏进程和监听
  → 撤销 token/密钥
  → 清理或隔离问题产物
  → 记录事件和影响范围
  → 修复后重新跑安全测试
```

在问题确认前，不得继续使用该模型、扩展或服务端配置。
