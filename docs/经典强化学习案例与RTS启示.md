# 经典强化学习案例与 RTS 启示

> 文档状态：v0.1
> 作者：周培智
> 目标：梳理 AlphaStar 之前的重要游戏强化学习案例，并说明它们对《铁锈战争》RL 平台的直接启示。

---

## 1. 先厘清“之前”指什么

“星际争霸之前的强化学习经典案例”可以有两种理解：

1. **AlphaStar 之前**：AlphaStar 2019 年登上《星际争霸 II》，此前已经有 TD-Gammon、DQN、AlphaGo、OpenAI Five 等经典案例。
2. **《星际争霸》强化学习之前**：在 PySC2、TorchCraft 和 AlphaStar 之前，RTS 研究更多来自传统游戏 AI、规划、脚本 AI 和 MicroRTS 这类小型环境。

这两个脉络对 IronZero 都重要：前者提供通用 RL 方法，后者提供 RTS 环境设计和动作抽象经验。

## 2. 通用游戏强化学习时间线

| 年份 | 案例 | 关键贡献 | 对 IronZero 的启示 |
|---|---|---|---|
| 1959 | Samuel Checkers | 自博弈、启发式搜索和机器学习结合 | 自博弈与评估对手池不是新概念，但必须可复现 |
| 1989 | Q-learning | 离策略时序差分控制 | 可作为教学基线，不建议直接用于复杂 RTS |
| 1992—1995 | TD-Gammon | 用时序差分和自博弈学习双陆棋 | 自博弈 + 价值估计可以超过手工评估 |
| 2013—2015 | DQN Atari | 从像素学习多款游戏，经验回放和目标网络 | 证明深度 RL 可行，但样本效率仍是问题 |
| 2015 | TRPO | 约束策略更新，提高稳定性 | PPO 的前身，适合连续/混合控制 |
| 2016 | A3C | 异步多环境采样 | 多环境思路可用于 RWPP 多实例，但首版先同步 |
| 2016 | AlphaGo | 策略网络、价值网络与 MCTS | 搜索与学习结合适合复杂决策，但 RTS 搜索空间巨大 |
| 2017 | PPO | 简化策略约束，工程稳定性好 | 本项目首选算法 |
| 2017 | AlphaGo Zero / AlphaZero | 纯自博弈、搜索与学习 | 自博弈可行，但依赖稳定环境和强搜索 |
| 2018 | OpenAI Five | Dota 2 大规模多智能体、长时程与自博弈 | 奖励塑形、对手池和长时程训练经验的直接参考 |
| 2019 | AlphaStar | 《星际争霸 II》大师级表现 | 动作抽象、模仿学习、联盟训练和摄像机视角的集大成者 |

## 3. RTS 与《星际争霸》相关早期案例

### 3.1 AIIDE StarCraft AI Competition / BWAPI

从 2010 年前后开始，AIIDE 的《星际争霸：母巢之战》AI 比赛使用 BWAPI 让脚本和规划智能体接入真实游戏。

特点：

- 使用真实游戏单位和规则。
- 观察、建造、生产和战斗都通过游戏 API。
- 早期强队主要是规则、状态机和搜索，不完全是端到端 RL。

启示：

- 真实 RTS 接口的价值首先在于“可观测、可控制”，不是立刻训练大模型。
- 环境桥接、动作合法性和单位控制，比算法选择更早成为瓶颈。

### 3.2 MicroRTS

MicroRTS 是一个小型开源 RTS 环境，保留资源、生产、单位和战斗，但规模远小于商业 RTS。

特点：

- 地图和单位数量可控。
- 适合微操、建造顺序和多智能体实验。
- 常被用于 RTS 规划、搜索和 RL 对比。

启示：

- IronZero 的第一阶段应该做 `micro_duel`，而不是完整 1v1。
- 固定地图、少量单位、关闭经济，是验证环境的正确起点。
- 胜负、单位价值差和战斗结果比“像人一样操作”更适合早期指标。

参考：

- https://github.com/santiontanon/microrts

### 3.3 TorchCraft

TorchCraft 为《星际争霸：母巢之战》提供机器学习接口，把游戏状态转换成可处理数据，并允许发送游戏命令。

特点：

- 连接真实游戏与 Python/Lua 训练程序。
- 抽象单位和命令，而不是模拟鼠标点击。
- 关注采样、命令延迟和游戏线程安全。

启示：

- IronZero Bridge 的职责与 TorchCraft 类似：状态序列化、命令回注、协议和错误处理。
- 动作必须是结构化命令，不应以屏幕坐标点击作为主要接口。

参考：

- https://arxiv.org/abs/1606.04650

### 3.4 PySC2 与《星际争霸 II》基准

DeepMind 在 2017 年发布 PySC2 和《StarCraft II: A New Challenge for Reinforcement Learning》，提供观测、动作、迷你游戏和回放接口。

特点：

- 提供多种观察格式。
- 将复杂动作分解成函数调用。
- 使用迷你游戏做课程学习。
- 支持回放和人类数据研究。

启示：

- IronZero 的 `Observation` 和 `Action` schema 必须版本化。
- 需要从微型任务逐步扩展到经济和完整对局。
- 回放、评估和人类数据接口应从一开始预留。

参考：

- https://arxiv.org/abs/1708.04782
- https://github.com/google-deepmind/pysc2

### 3.5 Relational Deep Reinforcement Learning

2018 年的关系型深度强化学习在《星际争霸 II》迷你游戏上使用实体关系编码，而不是把所有单位直接摊平成向量。

启示：

- IronZero 应该把单位视为实体集合，而不是一个固定长度的大向量。
- 实体数量变化时，Transformer、DeepSets 或关系网络比 MLP 更自然。
- 单位类型、队伍、距离和可见性都可以作为实体关系特征。

参考：

- https://arxiv.org/abs/1806.01830

### 3.6 OpenAI Five

OpenAI Five 在 Dota 2 中展示了长时程、多智能体、自博弈和奖励塑形的大规模训练。

启示：

- 长时程任务需要分阶段课程和奖励分解。
- 对手池和自博弈很重要，但不能取代基础环境验证。
- 观测必须限制在玩家可见信息内。
- 动作频率和“APM”约束会影响策略行为。

参考：

- https://arxiv.org/abs/1912.06680

### 3.7 AlphaStar

AlphaStar 在 2019 年达到《星际争霸 II》大师级水平，结合了模仿学习、强化学习、联盟训练、动作抽象和摄像机视角。

启示：

- 动作空间必须抽象成“选择单位、选择目标、选择位置”等分层决策。
- 战争迷雾要求模型具备记忆和不确定性处理能力。
- 单靠 PPO 和终局奖励不够，需要课程、对手池和可能的示范数据。
- 评估需要多地图、多对手和防过拟合。

参考：

- https://www.nature.com/articles/s41586-019-1724-z

## 4. 对本项目的直接决策

| 经典经验 | IronZero 决策 |
|---|---|
| BWAPI 先解决接口 | 先做只读 Bridge，再做动作桥 |
| MicroRTS 先做小环境 | 第一阶段固定 `micro_8v8` |
| TorchCraft 用命令而非点击 | 使用 `move_group`、`attack_move` 等结构化动作 |
| PySC2 用迷你游戏 | 采用 `micro → economy → full 1v1` 课程 |
| Relational RL 用实体编码 | 单位使用实体集合 + 注意力/DeepSets |
| OpenAI Five 用自博弈 | 先对原生 AI 和规则脚本，再做历史模型池 |
| AlphaStar 处理迷雾 | 只序列化本队可见信息，并保留最后可见记忆 |
| PPO 工程稳定 | 第一版采用 PPO + GAE + Action Mask |

## 5. 建议的训练阶梯

```text
A0  随机合法动作
A1  规则脚本
A2  micro_8v8：移动、集火、撤退
A3  固定经济：采矿、建造、生产
A4  战争迷雾与多地图
A5  对原生 AI
A6  自博弈与对手池
A7  LLM 战略 + RL 战术
```

不要从 A5 或 A6 开始。前面的环境、动作和评估基线不稳定时，复杂训练只会放大问题。

RWPP 的 API 依赖中列出 `game-lib:v2-1.15`，因此这条路线有明确的版本对应基础。但仍需实测：

- 1.15 资源能否被 RWPP 无头服务端加载。
- 扩展能否在游戏线程加载。
- 地图、单位和 AI 行为是否一致。
- 锁定版本后的 tick 是否稳定。

## 7. 一句话总结

**AlphaStar 之前最重要的经验不是某个算法，而是：先搭建真实、可观测、可控制的 RTS 环境，再用微型任务、动作抽象、实体编码、课程学习和对手池逐步扩展。**
