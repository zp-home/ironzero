## 一、A5（新发现，比 P0 更底层）：physics_ms 默认 0 -> 16

`--frame-ms` 同时是墙钟节奏和引擎物理步长（IronZeroBridge L162-168
`updateFrameInternal(1.0f, physicsElapsedMs)`）。默认 frame_ms=2 时：

    3600 tick x 2 ms  = 7.2 s 游戏时间  -> 双方 24:24 收场
    3600 tick x 16 ms = 57.6 s 游戏时间 -> 双方 19:19 收场
    20000 tick x 16 ms = 320 s 游戏时间 -> 双方 4:1 收场

25v25 在 7 秒内打不完，所以 terminal 不是"学不到"，是结构上不可达。
这正是 P0 修完后 kills/losses 全部变非零、而 terminal 仍是精确 0.000 的原因。

## 三、B5：invalid 的真实来源（不是 mask 的 bug）

原先 ACTION_MASKED 有 5 个来源，无法归因。细分后一轮实测：

    rejections: {TARGET_NOT_VISIBLE: 47, UNIT_NOT_OWNED: 112}   (70 episodes)
    ACTION_MASKED: 0

换算每局约 2.27 次 / 337 个决策 = 0.7%，invalid 约 -0.114/局。
两者都是"观测生成时目标/编组还活着，命令到达时已经全灭"的一帧延迟，
属于竞态而不是 mask 遗漏，因此不再是优先项。

## 四、还剩的真问题

1. **terminal 仍不可达**：即使 57.6 s，25v25 也只能打到 19:19。
   要么缩短战线（降单位数/加决胜条件），要么把 episode 拉到 300 s 以上
   （实测 320 s 时打到 4:1，仍是 timeout，说明纯坦克图本就难以全歼）。
   这不是奖励设计问题，需要先定"一局该怎么结束"。
2. **eval 与 train 的行为明显不一致**：a5b 那轮 train 的 own_hp 一度 0.99，
   final eval 却是 0.45；同一 checkpoint 在 probe 里 360 步只发 attack_target。
   怀疑确定性采样 + 单帧观测让策略在 eval 里退化成单一动作，待查。
3. **A4（engagement_coef 2.0 -> 0.3）仍然没做**，按原计划等 A1/A5 的效果先观测；
   现在 engagement 仍是 +0.12，是最大的正向塑形项之一，值得在 terminal 修好后重估。
