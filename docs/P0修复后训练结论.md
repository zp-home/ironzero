## 一、A5（新发现，比 P0 更底层）：physics_ms 默认 0 -> 16

`--frame-ms` 同时是墙钟节奏和引擎物理步长（IronZeroBridge L162-168
`updateFrameInternal(1.0f, physicsElapsedMs)`）。默认 frame_ms=2 时：

    3600 tick x 2 ms  = 7.2 s 游戏时间  -> 双方 24:24 收场
    3600 tick x 16 ms = 57.6 s 游戏时间 -> 双方 19:19 收场
    20000 tick x 16 ms = 320 s 游戏时间 -> 双方 4:1 收场

25v25 在 7 秒内打不完，所以 terminal 不是"学不到"，是结构上不可达。
这正是 P0 修完后 kills/losses 全部变非零、而 terminal 仍是精确 0.000 的原因。

## 三、B5：invalid 的真实来源（不是 mask 的 bug）

原先 ACTION_MASKED 有 5 个来源，无法归因。细分后一轮实测：

    rejections: {TARGET_NOT_VISIBLE: 47, UNIT_NOT_OWNED: 112}   (70 episodes)
    ACTION_MASKED: 0

换算每局约 2.27 次 / 337 个决策 = 0.7%，invalid 约 -0.114/局。
两者都是"观测生成时目标/编组还活着，命令到达时已经全灭"的一帧延迟，
属于竞态而不是 mask 遗漏，因此不再是优先项。

## 四、B6（新发现）：tick 上限裁决赛掉了明显的胜局

修完 A5 后 terminal 仍是 0，第二层原因在截断裁决本身。

**症状**：probe 实测一局打到 own=4 / enemy=1（双方都残血），
判定却是 timeout、terminal = 0.0 —— 赢了却一分不给。

**根因**：旧规则要求 hp 占比差 ≥ 0.08：

```python
if own_alive > enemy_alive and own_frac >= enemy_frac + 0.08:
```

但 hp_frac 是用**开局总血量**归一化的。长局打到后面双方占比都很小，
4 打 1 残血实测 own_frac=0.046 vs enemy_frac=0.040，只差 0.006，
永远够不到 0.08 —— **越是打到残局、越是明显赢，越判不出来**。

**改法**：主信号改成存活单位数，配比例阈值 `TIMEOUT_DECISIVE_RATIO = 1.25`：

| 情形 | 单位数比 | 判定 |
|---|---:|---|
| 4 vs 1 | 4.00 | victory |
| 8 vs 6 | 1.33 | victory |
| 21 vs 23 | 0.91 | timeout（确实没分出来） |
| 4 vs 14 | 0.29 | defeat |
| 双方全灭 | — | timeout |

第一版写成"单位数多 + hp 无劣势就判胜"，实测把 21 vs 23 误判成 defeat，
所以加了 1.25 倍比例阈值。另把两个魔法数提出来命名：
`TIMEOUT_TERMINAL_SCALE = 0.8`、`TIMEOUT_DECISIVE_RATIO = 1.25`。

**实测**：同一 checkpoint 连跑 4 局，**3 局产生了明确胜负**
（此前 100% 是 timeout）。

## 五、还剩的真问题

1. **terminal 在训练汇总里仍是 0.000**，但这是统计口径造成的：
   `reward_components` 是所有 episode 的均值，而 25v25 纯坦克图里
   大部分局打到 tick 上限时双方存活数仍在 1.25 倍以内（18 vs 22 = 1.22），
   按设计就是 timeout。要让它常驻非零，得先定"一局该怎么结束"：
   要么缩短战线（降单位数），要么把 episode 拉到 300 s 以上。
   实测 20000 tick（320 s）也只能打到 4:1 —— 纯坦克图本就难以全歼。
2. **eval 与 train 行为不一致**：final 那轮 train 的 own_hp 到 0.68，
   final eval 却是 0.33。同一 checkpoint 在 probe 里 900 步只发 hold。
   怀疑确定性采样 + 单帧观测让策略在 eval 里退化成单一动作，待查。
3. **A4（engagement_coef 2.0 -> 0.3）仍未做**。engagement 现在是
   +0.12 ~ +0.23，已是最大的正向塑形项之一，值得在 terminal 修好后重估。
