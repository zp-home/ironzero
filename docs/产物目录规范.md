# `runs/` 产物目录规范

> 本目录是**运行时产物区**，整体已在 `.gitignore` 中（第 25 行 `runs/`），
> **不进版本库、不提交、不打包分发**。

## 为什么要有这份规范

`runs/` 曾经是一个平铺的垃圾场：58 个顶层目录、67 个散落日志、919 个 `game-*.log`，
命名随意（`_smoke`、`_smoke25`、`_smoke_loop`、`_rwpp_ppo_smoke2/3/4`…），
既分不清「哪个是有价值的实验」和「哪个是一次性冒烟」，也没人敢删。

**核心原则：目录名必须能回答「这是什么、值不值得留」。**

---

## 1. 目录结构

```text
runs/
  platform/         # 平台运行时产物（后端与前端直接读写，禁止改名）
  recordings/       # 完整对局回放归档（ironzero.replay/1）
  experiments/      # 有保留价值的实验：带 checkpoint / 指标 / 评估结论
  archive/          # 一次性冒烟、基准、探针的最终归宿
  _rwpp_ppo/        # 真机 PPO 默认输出目录（RwppGameConfig.log_dir）
  _logs/            # 散落的运行日志、清单快照
  _scratch/         # 临时调试脚本（一次性探针，随时可整体删除）
```

### 各目录职责

| 目录 | 来源 | 可否删除 |
| --- | --- | --- |
| `platform/` | 后端 `/api/runs`、`/api/infer`、`/api/rwpp/*` 自动创建 | **否**，删了平台历史就没了 |
| `recordings/` | `record_rwpp_replay.py` 等落盘的对局 | 谨慎，是实验结果 |
| `experiments/` | 手工 `--out runs/experiments/<name>` | 有价值，按需归档 |
| `archive/` | 从顶层挪进来的 smoke/bench/probe | **是**，随时可整目录删除 |
| `_rwpp_ppo/` | `RwppGameConfig.log_dir` 默认值 | 是（会被重建） |
| `_logs/` | 各种 `*.log`、清单 CSV | **是** |
| `_scratch/` | 调试探针脚本 | **是** |

## 2. 命名规范

### 2.1 `experiments/` 下的实验

```text
<主题>_<方法或配置>[_v<版本>]
```

- 全部 **小写 + 下划线**，不用空格
- 不使用前导下划线（`_` 前缀专留给临时/草稿目录）
- 同一实验的不同配置用后缀区分，**不要用 `2`、`ft1` 这种无信息后缀**

```text
✅ econ_train_shaping_v2
✅ bc_ironzero25
✅ ironzero25_round1
❌ _smoke25          # 无信息 + 下划线前缀
❌ ironzero25_ft1    # ft1 是什么？应写 ironzero25_ft_lr3e4
❌ test123
```

### 2.2 一次性产物

**不要**在 `runs/` 顶层创建一次性目录，直接写到 `archive/`：

```powershell
python -m ironzero.training.train_rwpp --updates 2 --out runs/archive/_smoke_ppo
```

### 2.3 临时脚本

调试脚本一律放 `runs/_scratch/`，**不要**放仓库根目录或 `runs/` 顶层。
这些脚本的存在意义就是「用完即弃」，整个 `_scratch/` 可随时删除。

## 3. 代码依赖的固定路径（禁止改动）

这些路径被代码硬编码，**重命名会直接破坏功能**：

| 路径 | 引用位置 |
| --- | --- |
| `runs/platform` | `web/backend/app/paths.py` (`RUNS_ROOT`)、`IRONZERO_RUNS` 默认值 |
| `runs/_rwpp_ppo` | `src/ironzero/rwpp/config.py` (`log_dir` 默认值) |
| `runs`（递归扫描） | `paths.py::_resolve_checkpoint_roots` 的候选根 |

`/api/checkpoints` 会**递归**扫描 `runs/` 找 `*.pt`，所以把实验移进
`experiments/` 后**依然能被找到**——但**深度越大扫描越慢**，不要再加层级。

## 4. 清理策略

### 4.1 日常

```powershell
# 删掉每局游戏的 JVM 启动日志（每次跑都会重新生成，无分析价值）
Get-ChildItem runs -Recurse -File -Filter "game-*.log" | Remove-Item -Force
```

### 4.2 阶段性归档

把不再需要的实验整体挪进 `archive/`，而不是删除：

```powershell
Move-Item runs/experiments/某旧实验 runs/archive/
```

### 4.3 彻底清空

```powershell
Remove-Item runs/archive, runs/_logs, runs/_scratch -Recurse -Force
```

⚠️ **只清这三个**。`platform/`、`recordings/`、`experiments/` 里有真实实验数据。

## 5. 磁盘占用参考

| 目录 | 典型大小 | 说明 |
| --- | ---: | --- |
| `platform/` | 300–400 MB | 每次推理/训练都新增 `rwpp-live-*`、`real-rwpp-*` 目录，是增长最快的 |
| `archive/` | 30 MB | 一次性冒烟，可整删 |
| `experiments/` | 30 MB | 每个实验 1–3 MB（checkpoint 占大头） |
| `recordings/` | 20 MB | 大回放单个可达 2–3 MB |

**单个 checkpoint 约 0.7–1.1 MB**，158 个 `.pt` 合计约 114 MB。
`platform/` 里每个 `rwpp-ppo-*` job 都会写 3 个 checkpoint（`checkpoint` /
`_best` / `_latest`），这是磁盘增长的主要来源。

## 6. 新增产物时的检查清单

- [ ] 路径是否写进了 `runs/experiments/` 或 `runs/archive/`，而不是 `runs/` 顶层？
- [ ] 目录名是否符合 `<主题>_<方法>[_v<n>]`？
- [ ] 是否误用了前导下划线（`_` 只给临时目录）？
- [ ] 临时脚本是否放进了 `_scratch/`？
- [ ] 是否产生了 `game-*.log` 却没清理？
