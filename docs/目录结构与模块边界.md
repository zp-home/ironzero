# 目录结构与模块边界（重构规范）

> 本文件是本次架构重构的**唯一施工标准**。所有拆分必须遵守这里定义的边界、命名与兼容规则。
> 核心原则：**只搬结构，不改行为**（behavior-preserving refactor）。

## 1. 为什么重构

单文件体量失控，导致阅读、review、并发修改都极难：

| 文件 | 行数 | 主要问题 |
| --- | ---: | --- |
| `web/frontend/app.js` | 7497 | API + 状态 + 图表 + 沙盘渲染 + 全部页面逻辑塞在一个文件 |
| `src/ironzero/mock_engine.py` | 1132 | 常量 + 实体 + 出生点 + 动作校验 + A* 寻路 + 战斗 + 经济 + 观测 + 奖励 |
| `scripts/rwpp_real_service.py` | 1014 | 任务生命周期 + 子进程调度 + 手写 HTTP 服务 + 全部路由 |
| `src/ironzero/rwpp_env.py` | 944 | 进程启动 + socket 收发 + 动作解码 + 奖励塑形 + env + space |
| `web/backend/app.py` | 763 | 数据模型 + 任务存储 + 6 组路由 |
| `src/ironzero/training/ppo.py` | 636 | 配置 + rollout + GAE + update + 训练主循环 + checkpoint IO |

**目标：单个文件默认 ≤ 300 行，硬上限 450 行。**

## 2. 铁律（违反即返工）

1. **行为零变化。** 不修改任何数值常量、超参默认值、奖励系数、逻辑分支、正则、提示文案。
   - 允许的改动只有：移动代码、新增 `import`、新增 `__init__.py`、新增 re-export、必要时把
     `_private` 辅助函数搬到更合适的模块。
2. **旧 import 路径必须继续可用。** 用「薄 shim」模式：原文件变成只做 re-export 的转发模块。
   ```python
   # src/ironzero/mock_engine.py（shim）
   """兼容 shim：实现已迁移至 ironzero.engine。"""
   from .engine import *          # noqa: F401,F403
   from .engine import ACTION_KINDS, MicroDuelEngine, ...  # noqa: F401
   ```
   shim 内**不得**再写任何实现逻辑。
3. **不要动 `tests/`**（除非某测试文件自身超长且你被明确授权）。测试是回归安全网。
4. **不要 `git commit` / `git checkout` / `git reset` / `git stash`。** 只改工作区文件。
5. **不要改 `src/ironzero/training/train_rwpp.py`**，除非任务明确包含它。
6. **保留 monkeypatch 路径。** 测试里有这些硬依赖，拆分后必须仍然成立：
   - `ironzero.rwpp_env.subprocess.Popen`（⇒ shim 里必须保留 `import subprocess`）
   - `ironzero.training.train_rwpp.RwppPPOTrainer`
   - 私有成员：`engine._opponent_actions`、`engine._pending_reward`、
     `engine._move`、`engine._apply_one`、`env._safe_group`、`eval_script._resolve_micro`
7. **文件编码 UTF-8（无 BOM）、换行 LF、保留 `# SPDX-License-Identifier: Apache-2.0` 头。**
   Windows 控制台会把中文显示成乱码，**这是显示问题，不要因此改写文件内容**。
   用 `python -X utf8` 或 read 工具确认内容。
8. 每个新包都要有 `__init__.py`，其中写一句模块级 docstring + `__all__`。

## 3. 目标结构

### 3.1 `src/ironzero/engine/`（来自 `mock_engine.py`）

`MicroDuelEngine` 通过 **mixin 组合** 拆分。原类没有 `super()`、没有 `__slots__`、没有 `@property`，
所以 mixin 拆分是安全的等价变换。

```
engine/
  __init__.py       # re-export：MicroDuelEngine, MicroDuelAdapter, ACTION_KINDS 等全部旧公开名
  constants.py      # ORDER_NAMES/ORDER_IDS/ACTION_KINDS/*_TYPE_ID/TERRAIN_* 调参/错误码
  entities.py       # @dataclass Unit、MockResourceSlot
  config.py         # make_terrain_config()
  spawn.py          # SpawnMixin: reset() 的 spawn 相关 + _spawn_terrain_units()
  actions.py        # ActionMixin: apply_actions()/_apply_one()
  movement.py       # MovementMixin: _move/_move_terrain/_assign_group_path/_repath_terrain/
                    #   _path_stale/_reset_unit_path/_step_toward/_try_offset/_distance
  combat.py         # CombatMixin: _select_target/_visible_to/_damage/_check_done
  economy.py        # EconomyMixin: _calculate_income()/建造与生产相关分支
  observation.py    # ObservationMixin: observation()/_entity_payload()
  reward.py         # RewardMixin: _potential()/_reward_after_window()
  opponents.py      # scripted_actions()/_opponent_actions()
  engine.py         # class MicroDuelEngine(SpawnMixin, ActionMixin, ...): step/advance/查询/评估
  adapter.py        # MicroDuelAdapter
```

约定：
- mixin 内的方法只通过 `self` 访问状态，**不要**新增实例属性。
- `engine.py` 里保留 `step_decision` / `advance` / `_tick` / `alive_units` / `unit_by_id` /
  `snapshot` / `evaluate` 这些「编排」方法。
- `_tick` 会调用移动/战斗/经济，保持在 `engine.py` 或单独 `tick.py`，按内聚度决定。

### 3.2 `src/ironzero/rwpp/`（来自 `rwpp_env.py`）

```
rwpp/
  __init__.py       # re-export：RwppDuelEnv, RwppGameConfig, RwppEnvError, launch_rwpp_process,
                    #   decode_action, observation_to_state, apply_vision, hp_potential,
                    #   hp_fractions, army_hp_reference, army_distance_norm, DEFAULT_RUNTIME,
                    #   DEFAULT_JAVA_HOME, DECISION_TICKS, effective_frame_ms, _LineReader 等
  config.py         # RwppGameConfig, 默认常量(REPO_ROOT/DEFAULT_RUNTIME/...)
  errors.py         # RwppEnvError
  process.py        # _ProcLike, launch_rwpp_process(), effective_frame_ms()   ← 必须 import subprocess
  transport.py      # _LineReader（行协议读取）
  decoding.py       # observation_to_state(), decode_action(), _hold_action()
  vision.py         # apply_vision()
  reward.py         # hp_potential(), hp_fractions(), army_hp_reference(), army_distance_norm()
  spaces.py         # _BoxSpace, _MultiDiscreteSpace
  env.py            # RwppDuelEnv（reset/step/_observed/_refresh_strategy/action_masks/close/
                    #   _start_game/_await_observation/_shutdown_game）
```

`env.py` 里 `step()` 很长，允许抽成 `reward_shaping.py`（纯函数：
`compute_step_components(...) -> (components, terminated, ...)`），但**输入输出必须一一对应**，
且不得改变计算顺序（浮点求和顺序会影响 reward 末位，测试可能敏感）。

### 3.3 `web/backend/`

`web/backend/app.py` → 包 `web/backend/app/`（`__init__.py` 暴露 `app`，供
`uvicorn web.backend.app:app` 继续工作）：

```
web/backend/app/
  __init__.py       # from .server import app, create_app; __all__ = ["app", "create_app"]
  server.py         # create_app(): FastAPI 实例、CORS、static mount、include_router
  paths.py          # REPO_ROOT/RUNS_ROOT/FRONTEND_DIR/_resolve_checkpoint_roots/_resolve_inside
  models.py         # TrainRequest/InferRequest/RwppRecordRequest/RwppPpoRequest
  jobs.py           # 任务目录、meta 读写、_spawn、watch、_job_status、_read_jsonl、_tail
  routers/
    __init__.py
    system.py       # /api/health, /, /favicon.ico
    runs.py         # /api/runs*
    infer.py        # /api/infer*
    replays.py      # /api/replays*
    checkpoints.py  # /api/checkpoints
    maps.py         # /api/maps, /api/maps/{id}, /api/assets
    rwpp.py         # /api/rwpp/*（含 _rwpp_call 转发到宿主机服务）
```

**路由顺序与路径前缀必须逐字节保持一致**（前端按路径硬编码调用）。

### 3.4 `scripts/rwpp_real_service.py` → `scripts/rwpp_service/`

脚本入口必须仍是 `python scripts/rwpp_real_service.py --port 8300`。

```
scripts/rwpp_service/
  __init__.py
  state.py          # JOBS/JOBS_LOCK/PORT_SLOTS/ACTIVE_PROCESSES/STOPPED_JOBS/PPO_* 全局态
  proc.py           # _run_managed_proc, stop_job, stop_all_jobs
  paths.py          # REPO_ROOT/RECORDER/PLAYER/RUNS/_relative/_update/_append_replay
  runners.py        # _run_recorder, _run_player, run_infer, run_train
  ppo.py            # run_ppo, _read_live_events
  handler.py        # Handler(do_GET/do_POST/_send/...)
  server.py         # main(), ThreadingHTTPServer 装配
```
`scripts/rwpp_real_service.py` 变成 shim：`from rwpp_service.server import main`。
注意脚本目录不是包，需要 `sys.path.insert(0, str(Path(__file__).parent))` 才能 import `rwpp_service`。

### 3.5 `web/frontend/app.js` → `web/frontend/js/`（ES Modules）

`index.html` 的 `<script src="/static/app.js">` 改为 `<script type="module" src="/static/js/main.js">`。
**注意保留** `onerror` 兜底（改成加载 `./js/main.js`）。

```
web/frontend/js/
  main.js           # 仅一个 boot() 入口 + DOMContentLoaded
  api.js            # ApiBase/ApiError/api()/encodePathId
  util.js           # pickVal/num/clamp/fmt*/时间格式化/mulberry32 等纯函数
  normalize.js      # normalizeMap/Team/Unit/Event/Frame/Result/Replay、statusMeta、resultMeta
  state.js          # els、state、cacheEls()、createSandboxState()  ← 共享可变状态，全站单例
  demo.js           # buildDemoEvents/buildDemoBattle/initDemoData/demoReplayPayload
  connection.js     # startClock/renderConn/checkHealth/retryConnection/enterDemo/exitDemo
  train.js          # 训练监控：事件流、KPI、run 列表、start/stop
  charts.js         # niceTicks/drawLineChart/hexToRgba/chartSeriesConfigs/renderLegend/drawCharts
  replays.js        # checkpoint + 回放库
  rwpp.js           # 真机 RWPP 录制与轮询
  sandbox.js        # 沙盘：帧流/播放/相机/录制/状态
  camera.js         # 沙盘相机纯数学：全览基准几何、光标锚点缩放、平移、边界钳制（无 DOM）
  terrain.js        # 实机地图目录、地形预渲染、单位贴图
  render.js         # 沙盘 canvas 渲染（drawSandbox 等）
  dashboard.js      # Tab / 事件绑定 / 轮询 / 启动编排
  control.js        # 指挥中心大屏：实机推理（并发）+ 实机训练
  ppo.js            # 实机 PPO 训练
  model.js          # checkpoint/PPO 评估、LLM、奖励分解、战略指挥（fe* 收尾部分）
```

拆分规则：
- **不要改写函数体**，整体剪切粘贴。
- 每个模块 `export` 自己声明的函数/常量；跨模块引用改成 `import { x } from './y.js'`。
- 共享可变状态集中在 `state.js`：`export const els = {}` / `export const state = {...}`，
  其它模块 `import { els, state } from './state.js'`。**不要**重新赋值 `state`/`els` 本身
  （只能改属性），否则其它模块拿到的是旧引用。
- ES Module 循环依赖是允许的：函数声明会提升，运行时调用没问题。但**顶层立即执行**
  的代码不许依赖循环依赖里尚未初始化的 `const`。
- 必须消除所有「隐式全局」：重构后每个被引用的名字都要能从本模块 import 到。
