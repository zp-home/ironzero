# IronZero v1 协议说明

> 文档状态：v0.1
> 协议版本：`ironzero/1`
> Schema 版本：`1.0.0`
> 机器可读 schema：[messages.schema.json](../schemas/ironzero/1/messages.schema.json)

## 1. 传输层

首版使用：

```text
本机回环 TCP
+ NDJSON
一行一个 JSON 对象
```

约束：

- 只绑定 `127.0.0.1`。
- 单条消息最大建议 1 MiB，具体上限写入配置。
- 不允许一行内包含多个 JSON 对象。
- 不允许使用 NaN 或 Infinity。
- 发送前使用规范化 JSON 进行哈希和回放比较。

## 2. 消息信封

所有消息都有：

```json
{
  "protocol": "ironzero/1",
  "type": "step",
  "message_id": "m-0001",
  "episode_id": "e-0001",
  "tick": 120,
  "timestamp_ms": 123456
}
```

`timestamp_ms` 只用于诊断，不参与游戏时间判断。

## 3. 消息类型

| type | 方向 | 用途 |
|---|---|---|
| `hello` | 双向 | 握手、版本和能力交换 |
| `reset` | Python → 游戏 | 开始新 episode |
| `step` | Python → 游戏 | 提交决策动作 |
| `obs` | 游戏 → Python | 当前观测、奖励和状态标志 |
| `receipt` | 游戏 → Python | 动作执行回执 |
| `done` | 游戏 → Python | episode 结束 |
| `error` | 双向 | 协议或执行错误 |
| `heartbeat` | 双向 | 心跳和状态 |
| `shutdown` | 双向 | 安全关闭 |

## 4. 握手

Python 发送：

```json
{
  "protocol": "ironzero/1",
  "type": "hello",
  "message_id": "m-1",
  "adapter_version": "0.1.0",
  "game_version": "locked-version",
  "capabilities": ["ndjson", "action_mask", "lockstep"]
}
```

游戏扩展返回同名 `hello`，并声明自己的能力。双方版本不兼容时返回 `error` 并关闭连接。

## 5. Reset

```json
{
  "protocol": "ironzero/1",
  "type": "reset",
  "message_id": "m-2",
  "episode_id": "e-17",
  "seed": 42,
  "scenario": "micro_8v8",
  "map_id": "fixed_micro_01"
}
```

`episode_id` 必须唯一。reset 后第一帧必须是 `obs`，且 `tick` 从场景定义值开始。

## 6. Step

```json
{
  "protocol": "ironzero/1",
  "type": "step",
  "message_id": "m-3",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "actions": [
    {
      "kind": "attack_move",
      "unit_group": 1,
      "x": 1800,
      "y": 900
    }
  ]
}
```

第一版支持：

```text
move_group
attack_move
attack_target
stop
hold
```

## 7. Observation

`obs` 包含：

```text
meta
global_state
own_entities
visible_enemy_entities
remembered_enemies
local_maps
masks
reward
result          # null（对局进行中）或 victory / defeat（终局帧）
terminated
truncated
info
```

观测不能包含不可见敌人。实体列表必须使用固定槽位和掩码。

实体除位置/血量外还带建筑标记（真实桥接提供）：

```json
{
  "entity_id": 5,
  "entity_type_id": 2,
  "team_id": 1,
  "hp": 4000.0,
  "max_hp": 4000.0,
  "is_building": true,
  "is_factory": true,
  "is_builder": false,
  "is_operational": true
}
```

`entity_type_id` 只是便捷字段（1=移动单位，2=建筑），实际语义以布尔标记为准。

## 8. Receipt

成功：

```json
{
  "protocol": "ironzero/1",
  "type": "receipt",
  "message_id": "m-4",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "accepted": true,
  "executed_at_tick": 124
}
```

失败：

```json
{
  "protocol": "ironzero/1",
  "type": "receipt",
  "message_id": "m-4",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "accepted": false,
  "rejected_reason": "TARGET_NOT_VISIBLE"
}
```

## 9. Done

```json
{
  "protocol": "ironzero/1",
  "type": "done",
  "message_id": "m-5",
  "episode_id": "e-17",
  "tick": 18000,
  "result": "timeout",
  "reward": 0.0,
  "terminated": false,
  "truncated": true
}
```

`result` 语义：

| result | 触发条件 | terminated | truncated |
|---|---|---|---|
| `victory` | 引擎判定我方获胜（Artillery 图 `winCondition=mainBuilings`：敌方主基地被毁；或敌方队伍全部被消灭） | true | false |
| `defeat` | 引擎判定我方失败（我方工厂/建造单位全部损失，或全灭） | true | false |
| `timeout` | 到达 `--ticks`（`episode_ticks`）上限仍未分胜负 | false | true |
| `draw` / `failure` | 保留（平局/故障） | 按语义 | 按语义 |

真实桥接的终局流程：引擎判定胜负 → 发一帧 `obs`（`result` 已填、`terminated=true`）→ 立即发 `done` 并停止推进。因此：

- **不要**把 `done` 一律当作超时；`timeout` 只是“到 tick 上限仍未结算”。
- obs 的 `result` 与 `terminated` 是终局帧的提前通知；`done.result` 是权威值。
- 真实桥接不再硬编码 `result`；接入方必须原样透传（旧版桥接才会永远返回 `timeout`）。

`terminated` 和 `truncated` 必须分开处理。故障不能伪装成普通结束。

## 10. 顺序与去重

- 所有消息校验 `episode_id`。
- 同一 episode 的 `tick` 不得倒退。
- `decision_id` 不得重复。
- 过期 tick 的动作必须拒绝。
- 关闭后不再接受新消息。

```powershell
python -m unittest discover -s tests -v
```

协议模型与 schema 必须同时提交。
