# RWRL v1 协议说明

> 文档状态：v0.1
> 协议版本：`rwrl/1`
> Schema 版本：`1.0.0`
> 机器可读 schema：[messages.schema.json](../schemas/rwrl/1/messages.schema.json)

## 1. 传输层

首版使用：

```text
本机回环 TCP
+ NDJSON
一行一个 JSON 对象
```

约束：

- 只绑定 `127.0.0.1`。
- 单条消息最大建议 1 MiB，具体上限写入配置。
- 不允许一行内包含多个 JSON 对象。
- 不允许使用 NaN 或 Infinity。
- 发送前使用规范化 JSON 进行哈希和回放比较。

## 2. 消息信封

所有消息都有：

```json
{
  "protocol": "rwrl/1",
  "type": "step",
  "message_id": "m-0001",
  "episode_id": "e-0001",
  "tick": 120,
  "timestamp_ms": 123456
}
```

`timestamp_ms` 只用于诊断，不参与游戏时间判断。

## 3. 消息类型

| type | 方向 | 用途 |
|---|---|---|
| `hello` | 双向 | 握手、版本和能力交换 |
| `reset` | Python → 游戏 | 开始新 episode |
| `step` | Python → 游戏 | 提交决策动作 |
| `obs` | 游戏 → Python | 当前观测、奖励和状态标志 |
| `receipt` | 游戏 → Python | 动作执行回执 |
| `done` | 游戏 → Python | episode 结束 |
| `error` | 双向 | 协议或执行错误 |
| `heartbeat` | 双向 | 心跳和状态 |
| `shutdown` | 双向 | 安全关闭 |

## 4. 握手

Python 发送：

```json
{
  "protocol": "rwrl/1",
  "type": "hello",
  "message_id": "m-1",
  "adapter_version": "0.1.0",
  "game_version": "locked-version",
  "capabilities": ["ndjson", "action_mask", "lockstep"]
}
```

游戏扩展返回同名 `hello`，并声明自己的能力。双方版本不兼容时返回 `error` 并关闭连接。

## 5. Reset

```json
{
  "protocol": "rwrl/1",
  "type": "reset",
  "message_id": "m-2",
  "episode_id": "e-17",
  "seed": 42,
  "scenario": "micro_8v8",
  "map_id": "fixed_micro_01"
}
```

`episode_id` 必须唯一。reset 后第一帧必须是 `obs`，且 `tick` 从场景定义值开始。

## 6. Step

```json
{
  "protocol": "rwrl/1",
  "type": "step",
  "message_id": "m-3",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "actions": [
    {
      "kind": "attack_move",
      "unit_group": 1,
      "x": 1800,
      "y": 900
    }
  ]
}
```

第一版支持：

```text
move_group
attack_move
attack_target
stop
hold
```

## 7. Observation

`obs` 包含：

```text
meta
global_state
own_entities
visible_enemy_entities
remembered_enemies
local_maps
masks
reward
terminated
truncated
info
```

观测不能包含不可见敌人。实体列表必须使用固定槽位和掩码。

## 8. Receipt

成功：

```json
{
  "protocol": "rwrl/1",
  "type": "receipt",
  "message_id": "m-4",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "accepted": true,
  "executed_at_tick": 124
}
```

失败：

```json
{
  "protocol": "rwrl/1",
  "type": "receipt",
  "message_id": "m-4",
  "episode_id": "e-17",
  "tick": 120,
  "decision_id": "d-77",
  "accepted": false,
  "rejected_reason": "TARGET_NOT_VISIBLE"
}
```

## 9. Done

```json
{
  "protocol": "rwrl/1",
  "type": "done",
  "message_id": "m-5",
  "episode_id": "e-17",
  "tick": 18000,
  "result": "timeout",
  "reward": 0.0,
  "terminated": false,
  "truncated": true
}
```

`terminated` 和 `truncated` 必须分开处理。故障不能伪装成普通结束。

## 10. 顺序与去重

- 所有消息校验 `episode_id`。
- 同一 episode 的 `tick` 不得倒退。
- `decision_id` 不得重复。
- 过期 tick 的动作必须拒绝。
- 关闭后不再接受新消息。

## 11. 生成 schema

修改 Pydantic 模型后运行：

```powershell
python tools/generate_schema.py
python tools/validate_schema.py
python -m unittest discover -s tests -v
```

协议模型与 schema 必须同时提交。
