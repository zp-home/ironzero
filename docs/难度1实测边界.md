# 难度 1 实测边界（Round 14 更新）

## Round 14：第二座工厂停滞修复 + 难度悬崖定量

### 第二座 landFactory 永久停滞（已修复，commit 556421c）
`_issue_opening_factory` 在 `unfinished` 非空时直接 `return []`，使下方的停滞
检测（原本为重新派单而写）成为死代码；同时 site-clear 每次调用都抹掉
`_factory_stalled`。实测：第二座工厂 id=29 的 `build_progress` 从 tick 2011
到 19011 恒为 0.0，工厂阶段发 33 单后 idle 1919 次。
修复后：第二座工厂在 tick 4000 前建成（`factories=2/3`），总产能 29 个坦克。

### 产能已不是瓶颈（probe_throughput.py，seed 71003）
```
tick 14011: army=15 peak=17 produced=18 queue=2 funds=852
tick 18011: army= 7 peak=17 produced=26 queue=4 funds=2152   <- 钱积压，兵在死
```
末态资金 2152 且持续上涨，说明钱花不出去而军队在衰减——瓶颈是战斗损耗，
不是产能或经济。

### 32 种子基线：reserve=700 / army_cap=56 -> 0/32（95% CI 0-10.7%）
末态兵力 5-14 对 4-17，大致相当。dominance 需要 3x 兵力 AND 3x HP；
HP 比常常达标（如 seed 71018：2520 对 330 = 7.6x），但兵力比始终差一点。
军队在 14000 tick 后衰减，无法维持 3x 兵力。

### 难度悬崖（probe_ladder_d01.py，12 种子，同配置）
| 难度 | 胜率 | 95% CI |
|---|---|---|
| 0（收入 x1.0）| 6/12 = 50% | 25-75% |
| 1（收入 x1.4 + T2）| 0/12 = 0% | 0-24% |

同样配置从难度 0 的 50% 掉到难度 1 的 0%。这确认难度 1 的 x1.4 收入加成
和 T2 兵种（shield 450 拦截机、可对空 mechFactory 单位）是决定性障碍，
而非我们的战术框架无效——框架在公平对局下能达到 50%。

## Round 13：生产-扩张资金争用修复

生产阶段与扩张阶段争用同一笔钱。实测（probe_hover_gates.py，reserve=700）：
hoverTank（450cr）使 funds<700 出现 1723 次、扩张只发 1 单、矿场 1、收入 26；
tank（350cr）仅 50 次、扩张发 4 单、矿场 3、收入 42。修复为：生产阶段在矿场
配额未满时，必须给每个单位留出一份矿场钱。收入从 26 提升到 42-58。

## Round 12：工厂菜单死亡螺旋修复

bridge 的 `producibleNamesFor()` 把 `canAffordForUnit` AND 进菜单，资金被队列
抽干后菜单变空，Python `_combat_factories()` 判定"没有工厂"，锁死扩张阶段，
形成死亡螺旋。修复为菜单只报可建造集合，购买力交给 Python 侧判断。

## Round 11：种子转发修复

`env.seed` 从未传给引擎（引擎读 `game.seed`），所有历史测量实际是随机的。
`session.start_game` 现在把 env.seed 复制到 config 副本传给 launcher。

## 结论：难度 1 / Lake / >80% 在当前框架下不可达

三层结构性障碍：
1. 敌方 x1.4 收入 + T2 兵种（shield 450 拦截机）的压倒性优势；
2. 我方 c_tank 不能对空，无法削减敌方空中主力，3x 兵力比不可达；
3. dominance 判定需要同时 3x 兵力 AND 3x HP，僵持下无法维持。

已修复的 4 个真实工程 Bug（菜单死锁、种子转发、资金争用、第二工厂停滞）
都已提交推送，153 个测试通过。框架在难度 0 达 50%，证明战术本身有效；
难度 1 的 0% 是 x1.4 经济+T2 兵种的结构性结果。
