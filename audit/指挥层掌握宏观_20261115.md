## 0. 一句话结论

指挥层（LLM / 规则层）现在**能下达宏观经济指令**，并且这些指令**经实测改变了真实引擎的行为**：
取消进攻令 → 真实对局里 `attack_move` 由 272 次降为 0；
取消升级令 → `upgrade_building` 为 0；
降低进攻门槛 → 2 个兵就开打（272 次 `attack_move`）。
**但这不等于"策略学会了经济"** —— 经济仍由环境里的执行器按指挥层的计划执行，PPO 依旧不碰建造（见 §5）。

## 2. 新增的契约：`MacroPlan`

`strategy/directive.py` 新增 `MacroPlan`，挂在 `StrategicDirective.macro` 上。

| 字段 | 语义 |
|---|---|
| `build_order` | 哪些经济目标运行、**按什么优先级**。省略某目标＝取消它 |
| `army_target` / `army_cap` | 维持的兵数 / 生产停止的硬上限 |
| `max_extractors` / `max_factories` / `max_upgrades` / `max_turrets` | 各经济目标的额度 |
| `credit_reserve` | 不许花破的资金地板（保护工程车） |
| `attack_at_army` | 多少兵开始推进 |
| `engage_distance` | 距目标多近停止重发推进令 |

设计要点（都写进了代码注释）：

* **`None` = 无意见**。每个字段可空，空则用部署配置默认值。所以**空计划与改前行为逐字节一致**。
* 目标词汇 `MACRO_GOALS = (upgrade, extractor, factory, production, defence, expansion, attack)`，**顺序即默认优先级**（保留原有"升级先于生产、扩张先于进攻"的实测结论）。
* 计划**只能说要什么**，不含单位 id、坐标、建造队列、屏幕坐标 —— 下达者是执行器，不是 LLM。
* 交叉校验：`army_cap >= army_target`、`attack_at_army <= army_cap`；`build_order` 不许重复。
* 整个 `macro` 块非法 → **整条 directive 降级**（不让执行器去猜半个计划）。

## 3. 三处接线（这是"真的掌握"的关键）

### 3.1 规则层现在会规划（`strategy/rule_strategy.py`）

5 条规则，按紧迫度排序，**第一条命中的胜出**，每个分支只填它真有意见的字段：

| # | 触发 | 计划 |
|---|---|---|
| 1 | 己方 HP 比 < 阈值（军队被打残） | `production`/`defence` 提前，**移除 `attack` 与 `expansion`**，抬高兵数目标 |
| 2 | 己方单位数 < 敌方 | 生产/防御/升级/采矿提前，**移除 `attack`**，兵数提到敌方+2 |
| 3 | 资金 ≥ 2400 且有空矿点且无在建且已有兵 | **只抬高 `max_extractors`/`max_upgrades` 额度**，**不动优先级** |
| 4 | 己方数量占优且兵够 | 下调 `attack_at_army`（"已经占优，开打"） |
| 5 | 其余 | 空计划（无意见） |

> 规则 3 的第一版我把 `expansion` 提到最前，实测**更差**：真实对局里工厂链被饿死（`max_factories=0`）。这正是本仓库早就记录过的失败（`no_combat_factory` 1968/1968 决策）。已改为"只加额度、不动顺序"，并把这条教训写进代码注释与测试。

### 3.2 LLM 层现在能看见经济、也能被要求规划（`strategy/llm_strategy.py`）

* `SYSTEM_PROMPT`：新增 `macro.build_order` 的全部目标词汇、`null` 语义、交叉约束；同时**保留并强化**"不许控制单位、不许给坐标/建造队列"。
* `compact_summary` 新增 `economy` 块：`funds / income / extractors / factories / army / turrets / free_resource_slots / under_construction`。缺失字段渲染为 `null`（= 未知，用默认），**不会**伪造成 0。
* `DEFAULT_MAX_TOKENS` 400 → 700：payload 多了 10 个键，截断会导致 JSON 解析失败 → 整条 directive 降级，等于悄悄把指挥层踢出循环。

### 3.3 执行器读计划而不是读常量（`rwpp/env.py` + `rwpp/macro.py`）

* 新增 `rwpp/macro.py`：`ResolvedMacro`（已解析、已夹紧的计划）+ `resolve_macro(config, directive)` + `economy_summary(state)`。
  * **夹紧是必须的**：计划来自不可信来源，每字段都有 `LIMITS` 上下界，越界夹紧而非抛错；夹紧后再修复交叉矛盾。
  * **恒等解析**：无 directive / 空计划 → 返回配置默认值本身（`merged_with` 直接返回同一对象），保证改前行为不变。
* `env.py`：`self.macro` 在 `__init__`/`reset` 刷新；7 个 `_issue_*` 全部改读 `self.macro.*`，并在阶段入口加 `if not self.macro.allows(goal): return []`。
  * 全仓库已无 `self.game.economy_*` 的运行期读取（只剩注释）。
* `_curriculum_actions` 的固定元组改为按 `self.macro.stage_names` 遍历，**默认顺序与改前完全一致**。
* `stepping.strategy_payload` 同时输出 `macro`（指挥层要什么）、`resolved_macro`（实际执行什么）、`economy`（决策依据）——三者分开才能在 `live.jsonl` 里区分"没意见"和"被夹紧"。

## 4. 真实引擎 A/B（`.runtime/macro_ab.json`）

同地图（`[p2]Lake (2p)`）、同种子（11）、同难度（-2）、同策略（全程 `noop`）、同 tick 预算，**只改宏观计划**：

| 臂 | 计划要点 | steps | 结果 | `attack_move` | `upgrade_building` | 最高科技 | 工厂 | 兵 | 结束时资金 |
|---|---|---|---|---|---|---|---|---|---|
| A 默认 | 无 directive | 419 | victory | 0 | 2 | T2 | 2 | 6 | 553 |
| B 压制 | 取消 attack、`max_upgrades=0` | 298 | victory | **0** | **0** | T1 | 2 | 7 | 892 |
| C 强攻 | `attack_at_army=2`，attack 提前 | 422 | victory | **272** | 2 | T1 | 1 | 7 | 805 |

```json
{"plan_reached_the_executor": true, "stage_order_changed": true,
 "attack_fires_when_asked": true, "attack_suppressed_when_cancelled": true,
 "upgrade_fires_in_default_run": false, "upgrade_silent_when_max_upgrades_zero": true,
 "army_cap_respected": true, "economy_still_works": true}
```

读法（诚实版）：

* **能证明的**：计划到达执行器；阶段顺序改变；进攻令**能被要求出现、也能被取消**（272 vs 0）；升级令能被 `max_upgrades=0` 关掉；兵数上限被遵守；三臂都正常结束（没把经济搞崩）。
* **不能证明的**：A 臂 `upgrade_building` 只有 2 次且 `upgrade_fires_in_default_run=false` —— 该配置/时长下默认臂本来就没触发升级，所以"取消升级"这一项只由 B 臂的 0 次 + 单测锁定，**不由 A/B 对照证明**。
* 另外本轮顺带修掉一个**真实缺陷**：`_issue_late_expansion` 原本没有停滞门（stall gate），实测 366 决策里发出 **194 次** `build_extractor`（每 2 决策一次），每次都重置自己的施工。加锁存后降到 **17 次**。

python .runtime\probe_macro_ab.py

## 5. 边界：这次没有做到的事（必须说清）

1. **PPO 仍然不学经济。** `curriculum_owns_build_kinds=True` 仍把 `build_extractor` 恒关、`build_structure` 在施工期关闭。经济是"指挥层下计划、执行器执行"，**不是"策略学会了造矿"**。要让策略自己配平经济，需要接上已写好但从未接线的双槽动作布局（`decoding.ECONOMY_ACTION_KINDS` / `decode_action_multi`，动作头 5→10，检查点需迁移）。
2. **LLM 依然没在真跑。** 本轮只让它"能"规划（prompt + 解析 + 摘要 + 单测全部覆盖、全部 mock 网络）。环境变量 `IRONZERO_LLM_*` 仍未配置，真实运行仍然是 `RuleStrategy`。要真正启用：配 key + `--use-llm`；另外**推理侧**（`scripts/play_rwpp_policy.py`、Web 的 `RwppRecordRequest`）还没有 `use_llm` 参数，只在训练侧有。
3. **A/B 是单种子、单图、`-2` 难度、noop 策略、短局。** 它证明"接线通了"，**不**证明"这样打更好"。三个臂都是 victory，不构成战术优劣结论。
4. **规则层的 5 条规则没有经过胜率调优**，只有"为什么不这么写"的实测依据（见 §3.1）。它们现在是**可解释的默认意见**，不是最优策略。
5. 规则层**不 import `rwpp.config`**，所以它不知道部署的 `economy_army_cap`，只能用一个文档化的 16 作为上界，否则 `army_cap < army_target` 会让整条 directive 降级。
