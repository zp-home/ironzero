fix(rwpp): production queue wedge + stage starvation + expansion stall budget

Four measured defects in the seven-stage curriculum, each with the probe that
found it under scripts/.

1. produce_unit queued units the factory cannot build.
   The stage pinned the target head at target_slots-1, which decode_action
   resolves modulo produce_options() over every factory including the command
   centre. Measured (.runtime/queue_items.json): a land factory was ordered to
   build scout, which is absent from its menu, and queued[].progress stayed at
   -1.0 ("not started") from tick 1001 to 2751 while can_produce listed only
   [builder, hoverTank, tank]. A queue that never drains fills
   production_queue_depth, so the stage then read queue_full forever:
   factories=4, queue=3, funds=1624, army=0 for a whole episode.
   Fix: pick the target index from the option that belongs to a combat factory.

2. produce_unit blocked later stages.
   It sat in _order_blocks_later_stages shared set next to the build kinds, but
   it addresses a factory queue, not the builder. Measured
   (.runtime/production_plateau.json): production reported ORDERED on 1157 of
   1400 decisions and every one of them prevented attack from running, so the
   army never reached the gate it was waiting on.

3. attack dropped while outnumbered -- a deadlock.
   rule_strategy removed attack whenever own < enemy, but the only way to stop
   being outnumbered is to destroy enemy units. Fix: keep attack, drop
   attack_at_army to the army that actually exists (floored).

4. expansion stall budget shrank as the builder approached.
   _expansion_walk_budget was sized from distance_now, so the closer the builder
   got the sooner the leg was declared dead. Measured
   (.runtime/expansion_timeline.json): 894 -> 692 px of real progress, then a
   switch to a pool 1183 px away, then 1663 px; 23 orders, one extractor.

Also: economy ceilings are now reachable from the CLI (--army-cap,
--army-target, --max-extractors, --max-factories, --production-queue-depth,
--economy-reserve). The defaults were derived against an AI fielding 13-15 units;
at difficulty 1 the enemy holds 30-38, so army_cap=16 caps our army below half
the opposing force by construction.

Also: --debug-build config flag, which is what named the last defect -- the
bridge prints ordered=1 at (x,y) per accepted order, and the repeated
near-identical coordinates showed the build being restarted rather than the order
being lost.

Not achieved: difficulty-1 win rate is still 0%. The builder's distance to its
target pool still grows on most legs, so expansion does not complete and income
stays at 26 (one extractor of nine pools). 131 core tests pass.
