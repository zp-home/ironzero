fix(bridge): expose factory build state; queue production only at built factories

THE BUG
-------
The curriculum queued tanks at factory 27, whose observation advertised a menu
and reported is_operational=true, but whose engine state was
``isBuiltAndNotTransported=false, buildProgress=0.0``. Factory.update() returns
immediately while that flag is false, so the queue never advances: three tank
items sat at progress -1.0 for 19000 ticks, holding every production slot, and the
army stayed at zero while three land factories stood idle.

Decisive comparison (scripts/run_factory_diag.py):

    OURS    factory 27: builtNotTransported=false buildProgress=0.0 queue=3
    AI PILOT factory 27: builtNotTransported=false buildProgress=0.0 queue=3

Same factory state in both modes -- the AI simply queued at a factory that HAD
finished, while our code picked the first factory advertising a menu.
scripts/probe_ai_factory_units.py confirmed both modes queue the same ``c_tank``
type, so the type name was never the problem.

THE FIX
-------
* Bridge adds ``is_built`` to each factory entry in factoriesJson(), read from the
  engine's own isBuiltAndNotTransported().
* The production stage skips factories with is_built=false when choosing where to
  queue. The filter is deliberately scoped to production only: _combat_factories
  is also used by the build stage to decide whether another factory is needed, and
  filtering there stopped new factories from ever being built.

Note: an earlier insertion placed is_built INSIDE the can_produce array, producing
malformed JSON that silently collapsed the whole economy to one command centre.
The field is now a sibling of entity_id/unit_type/can_produce.

VERIFIED
--------
On Lake at difficulty 1, a full episode with a noop policy (curriculum only):

    own_mobile    : c_tank 21        (was: zero, or six scouts)
    own_buildings : commandCenter 1, extractorT1 2, landFactory 3, c_turret_t1 2
    closest_approach_px : 94.0       (was 865)

For the first time the production chain works end to end.
